📖 ML Methodology

Why Random Forest?

  • Handles non-linear daily/weekly seasonality without explicit decomposition
  • Robust to the spikes present in real network traffic
  • No GPU required — trains in seconds on 7,200+ records
  • Provides feature importance for explainability
  • Ensemble of 150 decision trees reduces overfitting

Feature Engineering

  • Temporal: Hour-of-day, day-of-week, month, day-index
  • Lag features: lag-1, lag-2, lag-3, lag-6 timesteps
  • Rolling stats: 3-step mean, 6-step mean, 3-step std
  • Categorical: Device type encoded as integer
  • Prediction: Recursive forecasting with lag updates

Evaluation Metrics

  • MAE — Mean Absolute Error (lower is better)
  • RMSE — Root Mean Squared Error (penalizes large errors)
  • R² — Coefficient of determination (1.0 = perfect)

Forecasting Pipeline

  • Load historical data from SQLite
  • Engineer lag + rolling features per device
  • Train Random Forest on 80% data, test on 20%
  • Recursive prediction: feed output back as new lag
  • Clamp predictions to valid range (0–99%)
